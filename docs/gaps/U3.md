# U3: Git and PR flow

## Verdict

**Verified for the missing action flow, with existing read-side groundwork.**
The worktree UI offers diff, external applications and removal, not commit,
push or PR creation (`src/screens/repos.jsx:130-161`). The workspace RPC
match exposes inspection, lifecycle and external-open operations, but no
commit/push/PR-create method (`src-tauri/src/workspace.rs:685-934`).
The claim should not be read as “no GitHub integration”: host-side PR listing
and detailed CI reads already exist (`src-tauri/src/workspace.rs:1104-1166`).

## Current state

- Philium creates isolated branches/worktrees and records their base commit
  (`src-tauri/src/workspace.rs:305-409`). Status includes dirty paths,
  unpushed/unmerged counts, upstream and the last commit, with corresponding
  worktree badges (`src-tauri/src/workspace.rs:412-472`;
  `src/screens/repos.jsx:143-150`).
- Diff inspection includes tracked changes against the recorded base and
  untracked-file previews (`src-tauri/src/workspace.rs:856-891`). Removal
  refuses unsaved work without explicit force
  (`src-tauri/src/workspace.rs:475-509`).
- Host `gh` subprocesses use the repo working directory, disable prompts,
  time out and return parsed JSON. PR lists are cached for 60 seconds, while
  command failures collapse to absent/empty data
  (`src-tauri/src/workspace.rs:1070-1150`). Detailed PR reads already request
  `statusCheckRollup`; code context renders check names and states
  (`src-tauri/src/workspace.rs:1153-1166`;
  `src-tauri/src/codeindex.rs:2739-2767`). This is agent-facing context, not
  the missing worktree action panel (`src/screens/repos.jsx:154-161`).
- Agents have read denials for SSH and gh credential paths, native HAL shell
  execution is denied, and execution is routed through Philium's shell tool
  (`src-tauri/src/agents.rs:173-196`). Agent sandbox setup nevertheless grants
  source `.git` writes so commits work: agent-side committing is possible,
  not a substitute for a deliberate human UI flow
  (`src-tauri/src/agents.rs:777-778`).
- HAL's dedicated Git tools are explicitly read-only `git_status` and
  `git_diff`; their runner is sandboxed and cancellation-aware
  (`../hal/src/tools/git.rs:1-41,57-102`). No new HAL mutation primitive is
  needed for host-controlled human actions.

## Where the fix lives

**Philium-only.** Add host-only typed operations in
`src-tauri/src/workspace.rs` and controls in `src/screens/repos.jsx`, alongside
those existing contracts (`src-tauri/src/workspace.rs:685-934`;
`src/screens/repos.jsx:130-161`). Reuse the read-side PR integration rather
than adding agent access to git/gh credentials
(`src-tauri/src/workspace.rs:1070-1166`;
`src-tauri/src/agents.rs:176-195`). HAL remains read-only for this lane
(`docs/LANES.md:13`).

## Proposed design

1. Add a worktree review panel: changed/staged files, branch/base, editable
   commit message and separate Commit, Push and Create PR actions. Request
   an agent-drafted message from bounded diff context as an optional suggestion.
   A draft is untrusted text, never authorization to execute an action.
2. Resolve registered worktree IDs server-side. Serialize mutations per
   repository because worktrees share metadata. Snapshot HEAD and staged
   content, then recheck before committing, rejecting changed inputs or active
   agent writers. Stage only explicitly selected paths with argv separation,
   never a blanket add of incidental files. Preserve unrelated staged work.
3. Implement typed host RPCs, not arbitrary shell strings or agent MCP tools.
   Require human confirmation of exact paths/message, remote/head and PR
   base/title/body. Commit, push and PR creation are separate durable steps.
   Use the user's installed git/gh and credentials only in host subprocesses.
   Do not copy tokens, credential files or credential-bearing environment
   values into HAL, agent shells, logs or model context.
4. Bound execution and output, drain pipes while running, redact errors and
   show actionable missing-tool/auth/signing/hook failures. Do not silently
   bypass hooks or signing. Account for repo-controlled hooks/config executing
   with host privileges by requiring a trusted repo and clear consent.
5. Push the explicit feature branch with normal fast-forward rules, never
   force-push. Resolve remote/base from actual repo configuration and user
   choice. Discover an existing PR for the exact remote/head/base before
   creation, so retries recover rather than duplicate. Persist completed
   steps and the returned PR URL without retrying successful publication.
6. Expose the existing detailed PR/check reader to the panel, adding exact
   head SHA and fetched-at metadata. Invalidate relevant caches after writes.
   Show pending/failure/success/unknown distinctly, and never display stale
   checks for a different head as current. Discover installed capabilities at
   runtime, without pinned client versions or model IDs.

## Acceptance checks

These are future implementation checks, not claims of execution in this
read-only grounding pass (`docs/gaps/README.md:15-22`).

- **Running-app workflow, macOS and Windows:** select a managed worktree with
  an agent's edit, inspect diff, obtain and edit its message suggestion,
  explicitly select paths, commit, push and create a PR in an authorized test
  repository. Verify the remote commit, intended base/head, exact message and
  returned URL independently. Reopen the panel/app and recover the same PR.
- Trigger actual remote CI, observe pending then the real result, push a
  second commit and ensure old-head results are not shown as current.
  With no checks or unavailable gh/auth/network, show unknown/actionable
  errors rather than an empty-success state.
- Cancel each confirmation and verify zero mutation. Test concurrent agent
  writes, stale HEAD/index, unrelated staged paths, filenames containing
  spaces/leading hyphens, detached HEAD, no upstream, rejected push,
  hook/signing failure and a timed-out PR request that actually succeeded.
  Retry must not duplicate a commit or PR, overwrite work, or force-push.
- Verify a peer worktree is unchanged, agent-visible tools cannot invoke the
  new publication RPCs, and credential canaries never reach agent context,
  shell environments, telemetry or errors. Validate hook/config trust consent.
- Add real temporary-repository integration tests for staging/concurrency and
  command failure boundaries, then run the normal regression suite. Do not
  count mocks alone as acceptance of authenticated publication.

## Dependencies and risks

- **I1 is not a prerequisite for reading CI on arbitrary user repos.** The
  reader already requests GitHub check rollups, independent of Philium's own
  CI pipeline (`src-tauri/src/workspace.rs:1153-1166`; `docs/GAPS.md:149-153,182-186`).
- U1's per-hunk review can share the panel later, but file selection and
  explicit staging need not wait for hunk accept/reject (`docs/GAPS.md:135-139`).
- Credential isolation and repo-controlled execution are the critical trust
  boundaries, given current credential denials and writable shared git
  metadata (`src-tauri/src/agents.rs:176-195,777-778`).
- No versions, model IDs or prices are needed. Any unavoidable fallback must
  obey the centralized pins rule (`AGENTS.md:5-7`).

## Size

**L.** Existing status/diff/PR readers reduce discovery work, but safe staging,
concurrency, host-credential publication, retry recovery and real authenticated
cross-platform acceptance make this more than adding three buttons
(`src-tauri/src/workspace.rs:412-472,856-891,1070-1166`).
