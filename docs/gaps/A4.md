# A4. Prompt caching on every request path

## Verdict

**Partly true.** Main Philium Claude traffic already receives cache breakpoints,
but native API-key `/messages` misses injection, and cache writes are not exposed
separately. The broad claim that HAL's missing `cache_control` means Philium
prompts are uncached is false: generated HAL models use the local gateway and
Anthropic-family chat requests are translated and marked there
(`src-tauri/src/providers.rs:299-324`, `src-tauri/src/gateway.rs:704-734`).

Philium desk and agent launches use `hal_setup`; it configures all enabled
providers as gateway-backed OpenAI-compatible transports, disables implicit
Claude CLI fallback, and hides login directories. Launch additionally scrubs
credential environment variables (`src-tauri/src/main.rs:100-118`,
`src-tauri/src/agents.rs:671-679,789-797`,
`src-tauri/src/providers.rs:299-331,354-360`, `src-tauri/src/hal.rs:115-124`).
Thus no normal generated Philium direct-HAL Anthropic bypass was found.
The comment claiming subscriptions use HAL login transports is stale relative
to the implementation (`src-tauri/src/providers.rs:287-309,354-359`).

Anthropic injection marks the last tool, system prefix and last two messages,
then caps known block locations to four. A shared-prefix marker separates
agent-specific prompt tails (`src-tauri/src/gateway/translate.rs:374-436,439-470`,
`src-tauri/src/agents.rs:715`). Existing helper tests cover ordinary bodies,
shared-prefix splitting, repeat injection and cap behavior, but do not prove
all HTTP routing branches (`src-tauri/src/gateway/translate.rs:752-829`).
The native subscription HTTP test checks OAuth, identity and redaction, not
cache placement (`src-tauri/src/gateway.rs:1578-1611`).

### Observability

Gateway activity already has `cached_tokens` for reads. Usage extraction adds
Anthropic read and creation tokens into total input, but returns creation tokens
only as part of that total, not as a separate field
(`src-tauri/src/gateway.rs:73-98,495-556`). Translation likewise preserves read
details but folds writes into prompt totals; streaming delta merging updates
reads, not creation (`src-tauri/src/gateway/translate.rs:363-371,550-552,578-582`).
Stats persist `tokens_cached`, and the UI displays cached totals/ratios, not
separate writes (`src-tauri/src/stats.rs:55`, `src-tauri/src/db.rs:93-96`,
`src/screens/stats.jsx:190-195`, `src/ui/conversation.jsx:549-565`). HAL's common
`Usage` cannot carry either cache dimension (`~/Developer/hal/src/provider/mod.rs:224-236`).

## Where the fix lives

**Philium-only for the app's A4 completion:** gateway routing, translation,
activity/stat storage and UI, since generated HAL traffic is already routed
through it (`src-tauri/src/providers.rs:299-324`). **HAL change** is additionally
needed if the requirement includes standalone HAL or cache metadata delivered
through HAL session usage: extend `provider::Usage` with optional cache-read
and cache-write fields and populate them in Anthropic/OpenAI parsers
(`~/Developer/hal/src/provider/mod.rs:224-236`,
`~/Developer/hal/src/provider/anthropic.rs:348-367`). No HAL edits in this lane.

## Proposed design

1. Centralize injection around the final outgoing Claude request shape. Include
   native Anthropic API-key `/messages`, retain post-guard redaction and OAuth
   identity behavior, and avoid accidentally marking unrelated endpoints.
2. Use discovered provider/model capabilities to identify Claude-compatible
   chat aliases, with explicit capability overrides where metadata is absent.
   Apply transport-supported tool marks and cap existing marks consistently.
3. Add optional cache-read and cache-write counters to gateway activity and
   persisted request rows. Preserve missing versus explicit zero, merge SSE
   usage without double counting, and expose both in request details and stats.
   Keep total input semantics explicit. Preserve these counters through chat
   translation, including final usage deltas.
4. Display per-request reads/writes from gateway telemetry rather than requiring
   a HAL change first. Correct the stale `hal_setup` transport comment.

- Exercise native `/messages` against the running authenticated app gateway for

  not pinned model IDs or guessed provider cache thresholds.
- This grounding ran code inspection only. No builds, app execution, upstream
  calls or acceptance tests were run, as required by `docs/gaps/README.md:15-17`.

## Dependencies and risks

- A5 needs distinct cache writes for correct cost attribution, not just today's
  combined input/read values (`docs/GAPS.md:107-113`, `src-tauri/src/gateway.rs:521-525`).
- Provider-specific compatible-chat behavior must be verified before adding
  Anthropic-only fields. Current compatible handling is a name heuristic, not a
  capability contract (`src-tauri/src/gateway.rs:727-732`). Resolve capabilities
  at runtime and keep unavoidable stale-sensitive literals in `pins.rs`
  (`AGENTS.md:5-7`).
- Preserve guard-before-shaping and secret-free gateway evidence. OAuth identity
  shaping is transport-sensitive (`src-tauri/src/gateway.rs:765-783`,
  `src-tauri/src/oauth.rs:510-518`).

## Size

**M** for Philium: injection exists, but routing coverage, persisted write
telemetry, translation and UI must agree. Standalone HAL parity adds a separate
upstream interface change. Rank as a coverage/observability gap, not a missing
cache implementation (`src-tauri/src/gateway/translate.rs:404-436`,
`src-tauri/src/gateway.rs:73-98`).
