# I6: Network blocking for sandboxed agents

## Verdict

**Partly true.** The claim that nothing demonstrates blocking is stale: Philium
has a default-deny Seatbelt profile with loopback-only network permissions,
strict-agent launch wiring, an authenticated egress proxy, and a macOS-only
`real_sandbox_probes` test (`src-tauri/src/sandbox.rs:220-264,515-575,934-944`,
`src-tauri/src/agents.rs:761-798`). This grounding is code inspection only,
not a claim that those tests or the running product passed.

The remaining gap is trustworthy integration proof. The current direct-egress
probe treats *any* failed curl as success, including an unreachable upstream;
the allowed-host probe targets loopback and retains lowercase `no_proxy`, so
it does not establish that the proxy carried the request
(`src-tauri/src/sandbox.rs:374-378,643-675`). The test launches a shell under a
profile, not an agent through the production launch path
(`src-tauri/src/sandbox.rs:615-617,631-642,936-944`).

## Current state

- Strict HAL launch receives proxy environment variables and a Seatbelt wrapper.
  HAL actually invokes the wrapper program and applies launch environment values
  (`src-tauri/src/agents.rs:761-798`, `src-tauri/src/hal.rs:109-133`).
- Seatbelt starts with `(deny default)` and allows outbound loopback plus local
  binds/inbound traffic. This is process-level enforcement, not merely a web UI
  CSP (`src-tauri/src/sandbox.rs:220-264`).
- The proxy checks per-agent authentication, evaluates the effective host list,
  returns 407/403 for rejected requests, forwards HTTP or CONNECT, and logs
  connection bytes (`src-tauri/src/sandbox.rs:515-575`). Host grants include
  settings and registered policy hosts, with exact or subdomain matching
  (`src-tauri/src/sandbox.rs:403-440`).
- Proxy credentials and policy hosts can be revoked
  (`src-tauri/src/sandbox.rs:357-360`). Existing proxy tests exercise allow/deny
  and policy grants separately from the real-profile test
  (`src-tauri/src/sandbox.rs:825-931,934-944`).
- `test_profile` creates a local upstream and compares command exit success to
  an expected boolean. It does not assert proxy audit attribution or a received
  nonce. Lowercase `no_proxy=127.0.0.1,localhost` survives the environment filter
  even though uppercase `NO_PROXY` is removed, making the loopback success probe
  potentially a direct connection (`src-tauri/src/sandbox.rs:374-378,643-675`).
- HAL already has configurable network guards, not just filenames: `Guard::new`
  consumes policy and sandbox configuration; its Linux process path conditionally
  starts an egress proxy. Those are separate from Philium's outer Seatbelt/proxy
  proof (`../hal/src/security/exo_network.rs:119-132`,
  `../hal/src/security/exo_process/linux.rs:134-150`).
- Unsupported platforms fail strict availability rather than supplying this
  macOS backend (`src-tauri/src/sandbox.rs:125-134`).

## Where the fix lives

**Philium-only** for the smallest I6 closure: improve `sandbox.rs` probes and add
an integration harness that uses `agents.rs` and `hal.rs` production launch
wiring. No HAL interface change is needed to prove the existing outer sandbox
(`src-tauri/src/agents.rs:761-798`, `src-tauri/src/hal.rs:109-133`). HAL remains
read-only for this task (`docs/LANES.md:13`).

## Proposed design

1. Replace negative-by-exit-code evidence with a controlled non-loopback
   upstream reachable by an unsandboxed control on the same machine/network.
   Require the control to receive a fresh nonce. If the control is unavailable,
   report the check blocked, never passed. Record the sandbox denial separately
   from DNS errors, timeouts and command-launch failures.
2. Explicitly clear both proxy bypass variables or use curl `--noproxy ''` for
   proxy-positive probes. Require the controlled upstream nonce and the matching
   agent/host/port audit row with positive transferred bytes. Exercise both HTTP
   and HTTPS CONNECT. Keep a loopback fixture for cheap offline proxy tests, but
   do not present it as non-loopback egress proof.
3. Launch an actual strict agent through the normal app path and execute a shell
   tool that unsets proxy variables and attempts direct IPv4/IPv6 TCP and UDP.
   Then exercise allowed and denied proxy hosts, missing/wrong credentials,
   allowlist changes, child processes, and revocation followed by a new connection.
4. Preserve explicit platform reporting: macOS is the current runnable matrix;
   Linux/Windows strict startup refusal is checked until I5 adds a backend.
   Do not treat platform skips as network-enforcement passes.

## Acceptance checks

- Automated real-profile test: unsandboxed positive control succeeds, identical
  direct sandbox traffic is denied, and allowed HTTP/CONNECT traffic produces a
  fresh upstream nonce plus attributable proxy audit evidence. An unreachable
  control must fail/block the test, never satisfy the negative check.
- Automated launch integration: use the production strict-agent startup path,
  run shell and child-process probes, remove all proxy variables for direct
  attempts, and verify forbidden proxy hosts cannot reach the upstream. Verify
  revocation rejects a fresh connection and reconnect provisions a new token.
- Real app workflow on macOS: configure a controlled allowlisted host in Sandbox
  settings, start an agent on an untrusted provider, ask it to fetch a fresh
  nonce using its shell tool, then attempt a non-allowlisted host and direct
  no-proxy egress. Inspect Sandbox egress rows for the actual agent, successful
  bytes and rejected host, repeat a second query, stop and restart the agent,
  and verify a peer agent's grants did not leak. Settings already loads sandbox
  status/allowlist and egress rows (`src/screens/settings.jsx:46-75`).
- Linux/Windows: verify strict startup refusal and visible error rather than
  silently exercising an unsandboxed substitute. Broader backend coverage is I5.

## Dependencies and risks

- **I1:** automate the macOS enforcement job without substituting a non-macOS
  skip; the current real-profile test is macOS-gated
  (`src-tauri/src/sandbox.rs:934-944`). **I5:** cross-platform backend work remains
  separate (`src-tauri/src/sandbox.rs:125-134`).
- Loopback is intentionally broad, not restricted to the proxy endpoint. A local
  forwarding service is therefore a threat-model boundary worth testing, not a
  promise of complete localhost isolation (`src-tauri/src/sandbox.rs:262-264`).
- Host policy is hostname-based and permits subdomains; the proxy resolves and
  connects after that decision. DNS rebinding/private-address policy needs an
  explicit decision before claiming protection against local-network pivots
  (`src-tauri/src/sandbox.rs:437-440,537-541`).
- Revocation removes credentials, while established streams forward until their
  copy completes. Do not describe revocation alone as immediate tunnel teardown
  (`src-tauri/src/sandbox.rs:357-360,571-575`).
- No runtime versions, model IDs or prices are needed. Preserve the runtime
  resolution rule for any future fixture dependencies (`AGENTS.md:5-7`).

## Size

**M.** Enforcement and a probe harness already exist; harden their evidence and
add production-launch acceptance rather than inventing another network sandbox
(`src-tauri/src/sandbox.rs:615-683,934-944`, `src-tauri/src/agents.rs:761-798`).
