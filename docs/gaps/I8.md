# I8. Frontend tests, lint, version mismatch

## Verdict

**Partly true.** The version mismatch is verified: the npm package declares
`1.0.0` (`package.json:3`), while both native manifests declare `0.1.0`
(`src-tauri/tauri.conf.json:4`, `src-tauri/Cargo.toml:3`). The claim of no
frontend tests is stale: existing Node-runner suites cover model selection,
draft restoration and RPC failures (`src/lib/model-list.test.js:1-36`,
`src/lib/drafts.test.js:1-65`, `src/lib/rpc-failures.test.js:1-29`).
The remaining gap is discoverable commands, lint configuration and CI wiring:
root scripts expose neither test nor lint, and root development dependencies
contain only the Tauri CLI, Vite and its Solid plugin (`package.json:5-19`).
A tracked/hidden-file search found no ESLint/Biome configuration or `.github`
workflow directory. This is an inventory observation, not evidence of test failure.

## Current state

- Philium already uses `node:test` and strict assertions, including meaningful
  asynchronous draft/peer isolation cases, not just placeholder tests
  (`src/lib/drafts.test.js:1-5,28-65`). RPC coverage checks failure thresholds
  and recovery (`src/lib/rpc-failures.test.js:7-29`).
- Additional render-side suites exist. For example, the conversation suite
  extracts source into a VM and checks reactive clocks, so it does not by itself
  demonstrate a running app workflow (`scripts/render/conversation-unit.test.mjs:1-35`).
  Its separate package declares a browser automation dependency but no scripts
  (`scripts/render/package.json:1`).
- Vite config supplies Solid transformation, a development server and a build
  target, not a test or lint entrypoint (`vite.config.js:1-9`). Existing lane
  acceptance requires Rust tests and a frontend build, not frontend lint/tests
  (`docs/LANES.md:53-56`). No test/build was executed during this grounding pass.
- Runtime status gets its version from the Cargo package environment
  (`src-tauri/src/main.rs:225`), and Settings About displays that status value
  (`src/screens/settings.jsx:739`). The Pilot override changes identity/window
  metadata without setting a version (`src-tauri/tauri.pilot.conf.json:1-5`).
- HAL is an independently versioned Rust package (`../hal/Cargo.toml:1-5`),
  launched as `hal-desktop-server` by Philium (`src-tauri/src/hal.rs:1,62`).
  HAL already derives its own release version from its manifest
  (`../hal/Makefile:10,48-56`). Its version need not equal Philium's.

## Where the fix lives

**Philium-only.** Change root npm commands, add lint/version-check tooling and
wire them into I1's CI. Version inputs are `package.json:3`,
`src-tauri/Cargo.toml:3` and `src-tauri/tauri.conf.json:4`; runtime display already
uses native metadata (`src-tauri/src/main.rs:225`, `src/screens/settings.jsx:739`).
No HAL interface change is needed for these frontend/build concerns
(`src-tauri/src/hal.rs:1,62`).

## Proposed design

1. Keep the existing Node runner. Add a root `test` command explicitly discovering
   `src/lib/*.test.js`, plus a documented command for render-side suites. Prove
   browser/Solid resolution requirements against the existing reactive tests
   rather than assuming a plain Node invocation covers them
   (`src/lib/drafts.js:1-2`, `scripts/render/conversation-unit.test.mjs:5`).
2. Add an ESLint flat configuration for Solid JSX and Node test/tooling contexts,
   with explicit generated/build output exclusions. Start with correctness rules,
   not wholesale style reformatting. Expose `lint` and run it without auto-fixing
   in CI. Resolve new tool versions from the live registry at implementation time,
   respecting `AGENTS.md:5-7`, rather than copying versions into this brief.
3. Choose one release authority, preferably Cargo because status already reads it
   (`src-tauri/src/main.rs:225`). Add deterministic tooling to derive npm/Tauri
   metadata from it, and a read-only check that fails on drift. Check lockfile
   root package metadata when applicable. Release updates use one command, while
   normal builds/CI reject mismatches instead of silently rewriting the checkout.
   Do not add another version literal to JS or Rust application code.
4. Have I1 call the root lint/test/version-check commands and retain the existing
   frontend build and Rust/pin checks (`docs/GAPS.md:182-186`, `AGENTS.md:7`).

## Acceptance checks

These are proposed implementation checks, not claims of validation in this pass.

- From a clean install, run the documented unit and render test commands, lint,
  version-drift check, frontend build and applicable Rust/pin regression checks.
  Report discovered test counts, including the existing model/draft/RPC suites
  (`src/lib/model-list.test.js:8-36`, `src/lib/drafts.test.js:7-65`,
  `src/lib/rpc-failures.test.js:7-29`).
- In a disposable checkout, independently introduce a failing assertion, a
  lint-detectable correctness error and a manifest mismatch. Each root command
  and its I1 job must fail. Restore changes and verify green again.
- Through the actual running native app, open Settings About and compare the
  displayed version with built bundle metadata and the authoritative manifest.
  Repeat for Pilot. The existing display and Pilot overlay are at
  `src/screens/settings.jsx:739` and `src-tauri/tauri.pilot.conf.json:1-5`.
- In the running app, compose text plus an image for agent A, switch to agent B,
  restart, verify A's restored draft and B's isolation, then send A's draft and
  confirm only sent content clears. This exercises the behavior covered only
  synthetically today (`src/lib/drafts.test.js:28-65`). Capture real workflow
  evidence separately from unit/VM results.

## Dependencies and risks

- **I1:** owns CI execution. Existing tests reduce setup effort, so classify I8
  as integration/coverage hardening rather than creating a test suite from zero
  (`docs/GAPS.md:182-186`, `src/lib/model-list.test.js:1-36`).
- **I2/I3:** release/signing/update work should consume the same native version
  instead of inventing a fourth authority; the current mismatch involves three
  manifests (`package.json:3`, `src-tauri/Cargo.toml:3`,
  `src-tauri/tauri.conf.json:4`). Choosing the release number is a release-policy
  decision, not automatically adopting the larger current value.
- Avoid brittle VM/source-text tests becoming substitutes for native acceptance
  (`scripts/render/conversation-unit.test.mjs:7-15`). Lint changes must not weaken
  the stale-pin guard (`AGENTS.md:5-7`). Keep HAL's independent release unchanged
  (`../hal/Makefile:10,48-56`).

## Size

**M.** Existing suites make runner adoption small, but reliable discovery,
Solid/Node contexts, lint rollout and three-manifest release synchronization
require coordinated tooling and CI work (`package.json:5-19`,
`src/lib/drafts.js:1-2`, `src-tauri/tauri.conf.json:4`).
