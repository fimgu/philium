## Current state
- Philium already parses unified hunk headers, tracks old/new line coordinates,
  and selects hunks. Selection text is bounded and handed to an agent draft
  (`src/ui/code-inspector.jsx:43-67,81-110`). This is reusable presentation, not
  a safe mutation patch: hunk selection itself stops at the preview limit
  (`src/ui/code-inspector.jsx:89-93,133`).
- Inspection compares the working tree with the selected graph base, including
  untracked files and rename paths, not separate index/worktree review layers
  (`src-tauri/src/codeinspect.rs:615-648`). Its revision is HEAD plus a constant
  working-tree suffix, not a digest of current dirty content
  (`src-tauri/src/codeinspect.rs:331-338`).
- Binary/truncated previews are explicit; base-only targets return no editable
  diff (`src-tauri/src/codeinspect.rs:615-648`). Existing path checks reject
  private paths, symlinks and repository escapes
  (`src-tauri/src/codeinspect.rs:242-283`).
- Other diff surfaces are plain patch previews: agent workspace and repository
  modal (`src/screens/agents.jsx:154-179`; `src/screens/repos.jsx:255,348`).
- Workspace exposes worktree lifecycle and diff RPCs, but no stage/unstage or
  hunk mutation RPC in its dispatch (`src-tauri/src/workspace.rs:685-939`).
  Repository locks and change invalidation already exist
  (`src-tauri/src/workspace.rs:30-35,165-168,785-803`).
- HAL has a guarded agent `apply_patch` tool with validation-before-write and
  rollback-on-failure, not a Git-index/review action API
  (`../hal/src/tools/patch.rs:215-245,249-303`). File helpers record hashes and
  sparse diffs through `file.changed` and database records
  (`../hal/src/tools/fs.rs:107-141,144-174`). Those primitives are partial safety
  infrastructure, not the requested review UI or an A1 restore contract.

## Where the fix lives
**Philium-only for U1's review and Git actions**, with an explicit dependency on
A1's chosen checkpoint interface for safe revert. Put mutation RPCs beside the
existing repository queue in `src-tauri/src/workspace.rs:30-35,685-939`, keep
read-only inspection in `src-tauri/src/codeinspect.rs:540-648`, and extend
`src/ui/code-inspector.jsx:114-138`. HAL need not gain a staging tool. If A1
lands upstream, consume its checkpoint API rather than invoking the model-facing
patch tool as a substitute for a deterministic user action.

## Proposed design
1. Add explicit comparison modes: base review, unstaged (index to disk), staged
   (HEAD to index). Keep base review distinct because its current patch includes
   committed branch changes (`src-tauri/src/codeinspect.rs:629-640`).
2. Return backend-generated file/hunk IDs plus fingerprints of HEAD, relevant
   index entries and disk bytes. A mutation accepts an ID, operation and expected
   fingerprint, never arbitrary client-supplied patch/path authority. Regenerate
   the full patch server-side and reject stale selections, including dirty edits
   that do not change HEAD. The current revision token cannot detect those edits
   (`src-tauri/src/codeinspect.rs:331-338`).
3. Add queued stage/unstage/revert operations at file and hunk scope. Construct
   patches from the correct layer, check then apply to the index or disk as
   appropriate, and refresh all views via the existing workspace signal
   (`src-tauri/src/workspace.rs:165-168`). Extend the subprocess helper with bounded
   patch stdin, since its current stdin is null (`src-tauri/src/workspace.rs:148-156`).
   Repository locking alone is insufficient against HAL/external writers: verify
   fingerprints immediately before mutation and fail closed on conflicts.
4. Define **Accept** as a persisted reviewed decision on an already-applied
   base-review hunk, not a second patch application or implicit stage. Bind the
   decision to content identity and expire it when content changes. Define
   **Reject** as checkpointed revert against the displayed comparison base.
   Label unstaged revert separately from rejecting committed branch changes.
   Confirm destructive actions and checkpoint affected bytes, existence and modes
   through A1 before changing disk, including accepted decisions in refresh state.
5. Add file toolbar and hunk controls with scoped keyboard shortcuts, focus and
   accessible labels. Use whole-file controls for binary/rename/mode changes;
   never mutate a partial preview. Preserve draft actions. Disable unavailable
   operations with explanations on base-only, conflicted or unsupported targets.

## Acceptance checks
These are required future checks, **not executed in this documentation pass**.
- Backend temporary-repository tests: two separated hunks, partial staged state,
  stage one, unstage one, revert one, and whole-file variants. Assert exact index
  and disk bytes, untouched hunks and unrelated files. Cover added/deleted files,
  renames, mode changes, binary files, CRLF and missing final newline.
- Test stale disk/index/HEAD, concurrent requests, malformed IDs, traversal,
  symlinks, private files, truncated patches and Git failure. Rejection must leave
  both index and disk unchanged. Checkpoint failure must block destructive edits.
- Real running app: open an agent worktree with two text hunks, inspect all three
  comparison modes, stage one by button and another by keyboard, then unstage one.
  Verify Git index and disk independently and observe refreshed Code, Repos and
  Agent diff surfaces. Accept a review hunk, reopen the view, and verify the
  decision persists without staging or reapplying it.
- In the app, reject one hunk and revert one file, confirm the checkpoint warning,
  then restore through A1 and verify exact bytes and file existence. Change disk
  externally while a hunk is selected and verify stale refusal and refresh.
  Repeat in another worktree and prove no peer worktree or draft is affected.

## Dependencies and risks
- **A1 blocks complete revert acceptance**, because U1 explicitly requires
  checkpoint integration (`docs/GAPS.md:135-139`; A1 contract at `59-70`).
- Coordinate the Git mutation interface with **U3**, whose scope includes commit,
  push and PR flow (`docs/GAPS.md:149-153`). U1 is more than adding buttons: the
  current base diff is not an index patch (`src-tauri/src/codeinspect.rs:629-640`).
- Preserve inspection path restrictions and model-tool access boundaries
  (`src-tauri/src/codeinspect.rs:242-283`; `../hal/src/tools/patch.rs:236-245`).
  Avoid shell interpolation, broad resets, cross-worktree path substitution and
  trusting preview text. External edits remain a race requiring explicit checks.
- No new model IDs, versions or prices are needed. Any future unavoidable pin
  must follow `AGENTS.md:5-7` and resolve runtime values where possible.

## Size
**L**: existing hunk presentation helps, but correct index layers, stale-content
validation, persisted review decisions, checkpointed destructive operations and
cross-surface refresh require coordinated backend and UI work.
