# U7. Shortcuts, onboarding, multi-agent grid

## Verdict

**Partly true, substantially stale.** The missing documented, complete agent shortcut
map remains a useful hypothesis, but the app already has more shortcuts than
⌘K and ⌘1-9, a getting-started checklist, and multiple live agent conversations
in Grid view. The global number shortcuts switch screens, not agents
(`src/main.jsx:165-183`). Onboarding and grid are incremental improvements,
not greenfield features (`src/screens/home.jsx:82-111`,
`src/screens/agents.jsx:722-859,1284-1299`).

## Current state

- Shell: Cmd/Ctrl+K toggles the palette; Cmd/Ctrl+1-9 selects a screen and
  ignores editable targets (`src/main.jsx:167-180`). The command registry
  supports screen-lifetime commands but contains no binding metadata
  (`src/lib/nav.js:15-20`). Agents registers New agent, Focus, Grid and Fleet
  commands (`src/screens/agents.jsx:1081-1087`).
- Additional bindings already exist: Enter sends and Shift+Enter inserts a
  newline in the shared composer, with IME protection
  (`src/ui/conversation.jsx:1049,1098`); Cmd/Ctrl+Enter submits the spawn form
  (`src/ui/spawn-modal.jsx:70-76`). Agent multi-selection supports Delete,
  Backspace and Escape outside editable targets
  (`src/screens/agents.jsx:1056-1064`). Browser has scoped Cmd/Ctrl+T/W/L/R
  (`src/screens/browser.jsx:100-107`). These distributed handlers, rather than
  a shared action/binding map, are the remaining shortcut-design problem.
- Home's Get started card links Add provider, Add repo and Start agent. Its
  checkmarks are based on nonempty collections, not a successful provider
  request or first response. Dismissal is component-local signal state
  (`src/screens/home.jsx:58,82-111`). Spawn success reports that an agent is
  starting, not that authentication and a first turn worked
  (`src/ui/spawn-modal.jsx:44-62`). A persisted non-Home route can bypass the
  Home checklist on startup (`src/lib/nav.js:4`).
- Provider setup already supports OAuth start/paste/cancel and model refresh;
  model-discovery errors are visible (`src/screens/providers.jsx:286-300,
  350-353,476`). Spawn's model picker consumes discovered enabled providers
  and offers Add provider when none exist (`src/ui/spawn-modal.jsx:91-104`).
- Grid is real chat, not just telemetry: each card loads agent events, merges
  live events, sends or queues messages and exposes approval/deny, cancel,
  stop and resume (`src/screens/agents.jsx:729-781,809-859`). View preference
  persists (`src/screens/agents.jsx:1068-1071`). Grid renders every tree entry;
  the `Math.min(..., 4)` expression only changes a CSS class, not the number
  of cards (`src/screens/agents.jsx:1286-1299`). CSS uses auto-fit columns and
  a scrolling wrapper, so it is not a bounded, pinned 2-to-4-chat workspace
  (`src/styles/agents.css:136-156`).
- HAL already exposes model listing and session creation routes
  (`../hal/src/server/mod.rs:455-463`); its documentation describes runtime
  discovery and explicit model selection (`../hal/README.md:204,282-283`).
  The missing presentation and onboarding completion criteria do not require
  a new HAL primitive.

## Where the fix lives

**Philium-only.** Extend the shell/action registry (`src/main.jsx:165-183`,
`src/lib/nav.js:15-20`), Home readiness flow (`src/screens/home.jsx:82-111`),
existing provider/spawn UI, and the existing agent Grid implementation
(`src/screens/agents.jsx:722-859,1284-1299`). No HAL change is proposed.

## Proposed design

1. Define action IDs, platform-aware shortcut labels, scope and enabled-state
   predicates in one frontend registry. Generate a searchable shortcut-help
   surface and palette entries from that map. Cover new agent, send, cancel
   current turn, switch agent, open diff and approve a focused request.
   Preserve existing bindings, including browser and IME behavior. Distinguish
   cancel-turn from stopping the agent process in labels and bindings.
2. Bind destructive or permission actions only to the focused agent/request,
   with no action when a modal, text editor or unrelated pane owns focus.
   Approval must never silently approve all requests or broaden grant scope.
3. Upgrade the checklist rather than add a parallel wizard: resumable setup,
   explicit retry, skip/reopen, provider connection and model discovery, optional
   repo where the role permits, then spawn and a successful first response.
   Track progress using observable readiness/results, not row counts. An
   unavailable provider must not get a green completion badge. Do not create
   paid probe requests without an explicit user send/confirmation.
4. Keep existing all-agent Grid and add a focused, stable 2-to-4-pane selection.
   Reuse live card event/message/permission paths. Preserve focused-agent
   identity as lists reorder, use stable IDs for persisted panes, and handle
   removed/stopped agents without accidentally retargeting a draft or action.
   Provide a narrow-window fallback rather than claiming four readable panes
   fit every display. Resolve provider/model choices from the live catalog.

## Acceptance checks

These are proposed acceptance checks, not execution results. This grounding
pass is read-only inspection; no app, build or test suite was run.

- In the running app on macOS and Windows, open shortcut help and exercise
  every documented binding with both modifiers appropriate to that platform.
  Create an agent, send twice, cancel a turn, switch agents, open its diff and
  approve one focused request. Verify visible target IDs and resulting state.
  Repeat with textarea/IME input, modal focus and browser tabs to detect
  collisions and accidental destructive actions.
- With fresh app data, connect an actual provider, discover its current models,
  optionally add a repo, start an agent and receive a real first response.
  Setup completes only after success. Exercise invalid credentials, discovery
  failure, user cancellation, restart/resume and manually reopening setup.
- In the running app, select 2, 3 and 4 real live agents. Send distinct prompts
  to each, observe independent streamed replies, queue a second prompt, cancel
  one turn and approve only one agent's pending request. Confirm peer agents,
  drafts and approvals are unaffected, including after sort/filter changes.
- Remove or stop a selected agent, reconnect/restart the app, resize to a narrow
  window and return to all-agent Grid. Check stable selection, clear recovery,
  no duplicate sends, and no hidden pane retaining an active shortcut target.
- Add registry/help consistency, editable-target and IME tests, onboarding
  readiness/retry tests and stable-pane selection tests. Run frontend tests,
  build and the existing stale-pin regression before implementation acceptance.

## Dependencies and risks

- No prerequisite HAL work. U4's steering/queue semantics and U1's diff action
  surface must remain consistent with shortcut dispatch; the existing card
  already distinguishes queue, cancel and stop
  (`src/screens/agents.jsx:762-771,814-820`).
- Approval shortcuts are a security boundary: retain explicit agent/request ID
  and scope (`src/screens/agents.jsx:780-781,843-844`). Do not bypass existing
  permission UI or expose credentials in progress persistence.
- Reuse provider discovery rather than hardcoding model/version choices, per
  `AGENTS.md:5-7` and `src-tauri/src/providers.rs:13`. Grid rendering/event
  subscriptions should stay bounded for pinned panes while preserving the
  existing full-grid mode (`src/screens/agents.jsx:748-755,1286-1299`).
- Ranking change: reduce the weight assigned to missing onboarding/grid.
  Both exist; prioritize safe action discoverability and proof of first-run
  success over building replacements (`src/screens/home.jsx:94-111`,
  `src/screens/agents.jsx:836-859`).

## Size

**M.** Extend existing UI paths with a shared action map, verified setup progress
and bounded pane selection, rather than implement new HAL or chat infrastructure.
