## Verdict
**Verified.** The shared composer stores textarea input verbatim and handles Enter as send, without an @ picker (`src/ui/conversation.jsx:1047-1049`). Its final submission expands `/skill`, then delivers text plus images, not file/symbol/URL selections (`src/ui/conversation.jsx:968-976`). The audit's `@` hits are not mentions: agents render `repo@branch` labels, while terminals import scoped xterm packages (`src/screens/agents.jsx:800,872,882`; `src/screens/terminals.jsx:11-13`).

## Current state
- The full agent view uses shared `Composer`, passing text/images to `agents.send` or `agents.queue_add` (`src/screens/agents.jsx:504-513,674`). The compact agent card has a separate plain-text send form and sends an empty images list (`src/screens/agents.jsx:762-771,847-857`). Both entry points need an explicit scope decision.
- Image attachment previews/removal already provide a partial attachment UX, but are explicitly image-only (`src/ui/conversation.jsx:981,1025-1027,1053-1058`). Draft-backed images and text already exist (`src/ui/conversation.jsx:778-780`), so context selection should extend that lifecycle rather than replace it.
- Codeindex is already structural, worktree-aware and incremental, with a base snapshot plus deltas (`src-tauri/src/codeindex.rs:1-12`). `find` returns structured symbol items and `tree` returns files (`src-tauri/src/codeindex.rs:19,23,2488-2492`); fuzzy name matching already exists (`src-tauri/src/codeindex.rs:1235-1268`). This is not a missing-index project.
- Codeindex exposes `source` inspection through RPC and resolves target context before dispatch (`src-tauri/src/codeindex.rs:2444-2450`). Existing agent MCP tools expose maps, outlines, exact symbol source and fuzzy search (`src-tauri/src/codeindex.rs:2972-2980`). These are agent tools, not composer selection UI.
- Philium sends `{text, images, allow_browser}` to HAL, and queued messages persist text/images (`src-tauri/src/agents.rs:1328-1342,1347-1355,1765-1777`). HAL's client already accepts text and images, while its local input builder handles pasted, dropped and staged images (`../hal/src/client.rs:383-399`; `../hal/src/input.rs:32-35,66-83`). No new HAL primitive is required for bounded text context.
- Network policy primitives already include per-agent allowlists and host checks, with an authenticated CONNECT-aware proxy (`src-tauri/src/sandbox.rs:346-349,403-438,522`; `src-tauri/src/sandbox.rs:878-879`). Browser URL normalization accepts HTTP(S), but that is not a composer attachment fetch API (`src-tauri/src/browser.rs:69-81`; `src/ui/conversation.jsx:968-976`).

## Where the fix lives
**Philium-only.** Extend the shared composer and draft model, add backend context-resolution RPCs, reuse codeindex, and serialize bounded context into the existing HAL text message. Main seams: `src/ui/conversation.jsx:760,968-976`, `src/lib/drafts.js` (already imported at `src/ui/conversation.jsx:17`), `src-tauri/src/codeindex.rs:2441-2450,2488-2492`, and `src-tauri/src/agents.rs:1328-1355`. HAL stays read-only and its existing input interface suffices (`../hal/src/client.rs:383-399`).

## Proposed design
1. Add caret-aware `@` token detection, debounced file/symbol suggestions, keyboard navigation and an accessible listbox. Reuse `codeindex.find` and `tree`, always targeting the selected agent's worktree rather than a global active repo. Add explicit URL selection when the token is HTTP(S). Keep literal email addresses and unselected @ text untouched. Integrate compact cards with the same picker or visibly route context attachment to the full composer.
2. Represent selected context as removable chips with kind, repository/worktree identity, path/line span or canonical URL, preview and loading/error state. Persist the descriptors with the draft. Clear only the submitted snapshot on successful delivery, retaining failures and edits made during a send.
3. Resolve file/symbol content on the backend within the agent's authorized root/grants, validating canonical paths and symlinks. Reuse source inspection and add bounded UTF-8 file reads where necessary. Show the selected revision and require confirmation/reselection if source changed before send. Cap per-item and total bytes/tokens, and report truncation instead of silently dropping content.
4. Add a policy-bound URL fetch service using the selected agent's egress identity and allowlist. Enforce HTTP(S), redirect-hop checks, DNS/private-address controls, timeouts and response limits. Never use an unrestricted host-side request as a shortcut. Display fetch failures before send. Treat fetched text as untrusted content, not instructions, and render escaped text only.
5. Append labeled, escaped source-context sections to outgoing text before `agents.send` or queue insertion. Freeze resolved content at enqueue time so later worktree/web changes do not silently alter queued messages. Preserve source labels in the transcript text. Structured HAL attachments can be a later enhancement, not a prerequisite.

Verify the actual submitted/transcript content and the agent's answer contain the selected worktree version, not the base checkout. Send a second message with no selection and verify context does not leak.
- While that agent is busy, select a symbol and enqueue a message. Edit its source afterward. Verify delivery uses the previewed snapshot. Exercise queue take-back/edit, failed-send retry, draft restoration, agent switching and compact-card entry without cross-agent context bleed.
- Attach an allowed URL, inspect fetched context, then send and verify receipt. Repeat with a denied host, redirect to a denied/private destination, oversized response and timeout. Retain image paste/drop, `/skill`, normal Enter/Shift+Enter and IME behavior.
- Add unit/integration checks for token parsing, stale-query cancellation, target isolation, path/redirect enforcement, truncation and frozen queue serialization. Then run applicable Rust regressions and the frontend build. No build or app run is authorized by the grounding brief (`docs/gaps/README.md:15-22`).

## Dependencies and risks
- A6 overlaps only in reusable code intelligence/fetch services: codeindex search/source tools already exist, so U2 must not wait for a replacement index (`src-tauri/src/codeindex.rs:2972-2980`).
- I6 is a security dependency for URL context: reuse and test the existing per-agent allowlist/proxy path rather than assuming the composer inherits sandbox enforcement (`src-tauri/src/sandbox.rs:346-349,403-438,522`). File context must also honor existing external-access grants, not only worktree paths (`src-tauri/src/agents.rs:236`).
- U4 intersects the queue lifecycle, which currently joins queued text and flattens images (`src-tauri/src/agents.rs:1347-1355`). Freezing context before enqueue avoids requiring a new HAL queue protocol.
- No model/version/price literals are needed. Preserve the runtime-resolution rule (`AGENTS.md:5-7`). Main risks are unauthorized file/URL disclosure, unbounded context cost, stale previews and draft leakage between targets.

## Size
**L.** The index and HAL text transport already exist, but secure context resolution, policy-bound URL fetching, accessible selection and draft/queue lifecycle integration remain distinct work (`src-tauri/src/codeindex.rs:19,23`; `src-tauri/src/agents.rs:1328-1355`; `src/ui/conversation.jsx:1047-1058`). Keep ranking as a verified UX gap, with less index work than the original claim might imply.
