# A1. Undo and checkpoints for file edits

## Verdict

**Partly true.** General per-turn undo/checkpoint restore is missing, but the
claim understates existing protection: HAL checks read hashes, persists sparse
before/after diffs, and attempts in-memory rollback of partially failed patches
(HAL `src/tools/fs.rs:62-104,107-175`, `src/tools/patch.rs:297-344`).
The persisted history is not a full byte snapshot or a turn-indexed restore
journal (HAL `src/session/db.rs:243-253,1354-1388`). Philium's Changes panel
provides inspection, terminal, review and refresh, not undo
(`src/screens/agents.jsx:153-179`). Keep A1 high priority, but build on these
primitives rather than introduce a second independent mutation path.

Evidence below uses Philium-relative paths and `HAL` for `~/Developer/hal`.
This is a source-grounding pass, not a running-product acceptance result.

## Current state

- `edit` and `write` read the current content and call the shared
  `commit_change` helper (HAL `src/tools/edit.rs:71-103`,
  `src/tools/write.rs:52-72`). That helper writes first, then emits a hash/diff
  event and records history with an ignored database result. It does not
  durably preserve preimage bytes before mutation (HAL `src/tools/fs.rs:107-141`).
- Deletion similarly removes the file before recording a diff to empty;
  `base_hash`/`result_hash` distinguish creation/deletion, but the history table
  stores neither complete bytes nor turn IDs (HAL `src/tools/fs.rs:144-174`,
  `src/session/db.rs:243-253`). Read-before-edit rejects binary files, and
  decodes text with loss replacement, so existing text diffs are not a universal
  byte-exact recovery format (HAL `src/tools/fs.rs:76-103`).
- Multi-file patch retains originals only in memory. On a later write failure
  it attempts reverse writes/removals and ignores rollback errors. Earlier
  emitted change events are not undone in that branch
  (HAL `src/tools/patch.rs:297-344`, `src/tools/fs.rs:127-140`).
- Shell/non-tool change detection partly exists upstream: when
  `exo_generated_files` is enabled, runtime saves a turn-start workspace
  baseline and emits observations at turn completion
  (HAL `src/agent/runtime.rs:1616-1634,1917-1931`). The baseline contains file
  metadata, not content, and observations report status/result hashes with
  bounded/truncated coverage. Non-Unix scanning is unsupported
  (HAL `src/file_artifacts.rs:11-33,280-351`). This is detection groundwork,
  not recoverable snapshots or evidence that Philium enables/displays it.
- HAL has specialized controlled-study snapshot/promotion/rollback behavior,
  explicitly tied to a permanently guarded study session. It is not general
  conversation-turn undo (HAL `src/tools/study.rs:1-8,970`).
- HAL exposes file history and diff reads, alongside workspace-edit submission
  and receipts, but no checkpoint/restore route in that route group
  (HAL `src/server/mod.rs:490-502`). Philium currently inspects worktree diffs
  (`src/screens/agents.jsx:153-179`). Its `/fork` spawns an agent using the
  current branch and a brief, not a selected-turn filesystem snapshot
  (`src/screens/agents.jsx:571-580`).

## Where the fix lives

**Both.** HAL must own durable capture and checked restore at the mutation
boundary in `src/tools/fs.rs`, plus patch transaction coordination in
`src/tools/patch.rs`, turn association in `src/agent/runtime.rs`, persistence in
`src/session/db.rs`, and authenticated endpoints in `src/server/{mod,sessions}.rs`.
These are the existing mutation/history/turn/API seams cited above.
Philium should proxy checkpoint operations through `src-tauri/src/agents.rs`
and render turn/file restore controls in `src/screens/agents.jsx`, adjacent to
its current `agents.diff` consumer (`src/screens/agents.jsx:153-154`).
HAL remains read-only for this grounding task (`docs/LANES.md:13`).

## Proposed design

1. Add a session/workspace-scoped content-addressed byte store and durable
   mutation journal. Persist preimage, existence, mode, expected postimage hash,
   turn ID and operation ID before permitting any write/delete. Coalesce a
   file's earliest preimage per turn while preserving ordered mutations.
   Refuse mutation if capture cannot be made durable; expose capacity failures.
2. Journal prepared/applied/recovered states so crash recovery can reconcile
   interrupted writes. Route patch failure rollback through the same checked
   transaction primitive and reconcile events/hashes, rather than raw writes.
3. Expose `GET /sessions/{id}/checkpoints` and
   `POST /sessions/{id}/checkpoints/{turn}/preview` and `/restore`; return paths,
   availability, conflicts and a durable operation receipt. A request selects
   a turn boundary and optionally paths. Restore means state before that turn,
   including reversal of later affected changes. Validate all expected live
   postimages before any write, reject conflicts without overwriting user work,
   serialize workspace writers, and journal restore itself as a new operation.
4. Use no-follow workspace-relative access and the same authorization/security
   boundary as normal mutations. Never reset Git or touch its index. Restore
   creation as absence, deletion as exact bytes, and preserve file modes.
5. Reuse bounded artifact observation for shell-edit warnings, showing explicit
   unsupported/truncated coverage. Do not advertise shell rollback unless
   before-bytes were actually captured. Provide the warning in the turn UI.
6. Keep checkpoint lineage workspace-specific. `/fork` must not silently restore
   its source workspace. Define later snapshot-based forks explicitly, and
   protect referenced blobs from retention cleanup. Cap bytes/age per workspace
   and make expired/unavailable checkpoints visible.

## Acceptance checks

These are required future checks, not tests executed by this docs-only task.

- In the running Philium app, use a disposable worktree with dirty committed
  and untracked files. Have one turn edit a file twice, create another and
  delete a third via patch. Preview and undo the turn, verifying exact bytes,
  absence/modes and preservation of pre-existing user changes and Git index.
- Run a second modifying turn, restore an earlier boundary for one file, then
  restore the whole turn. Verify unrelated paths and a peer agent/worktree are
  unchanged. Restart the app/HAL and repeat from saved history.
- Repeat outside a Git repository. Modify a target manually after the agent's
  turn and verify restore reports a conflict without any partial overwrite.
  Test running-turn restore rejection or safe writer serialization.
- In-app shell edits must produce an explicit non-restorable-change warning,
  including cancelled turns and truncated/unsupported scan coverage. Verify
  behavior on each supported platform, not only Unix.
- HAL regression tests must cover durable capture failure, crash between
  prepare/write/finalize, patch rollback failure, deletion versus empty file,
  exact bytes, symlink/path escape, retention, concurrent writers and restore
  authorization. `/fork` must leave source files/checkpoints unchanged.

## Dependencies and risks

- U1 should share restore preview/conflict primitives, rather than independently
  reverse diffs; U5 needs the same turn-boundary and fork-lineage semantics
  (`docs/GAPS.md:135-139,161-164`). No need to block basic A1 on either.
- Preimages can contain secrets and substantial data. Keep them private to the
  local session/workspace, bound retention, and avoid content in diagnostic
  events. Restore must not bypass sandbox rules or overwrite newer user edits.
- Existing sparse history is insufficient for guaranteed byte-exact migration;
  label older turns unavailable rather than manufacture recoverable snapshots
  (HAL `src/session/db.rs:243-253`, `src/tools/fs.rs:76-103`).
- No model/version/price literals are needed. Preserve runtime resolution rules
  (`AGENTS.md:5-7`).

## Size

**L.** Durable cross-tool recovery, conflict-safe multi-file restore and restart
semantics span HAL persistence/runtime and Philium UI. Detection groundwork
reduces shell-warning work, but does not supply recoverable preimages.
