# I5: Non-macOS sandbox

## Verdict

**Partly true.** Philium implements only the macOS Seatbelt backend. Linux's
Landlock variant explicitly returns an error and Windows selects Unsupported
(`src-tauri/src/sandbox.rs:105-135`). However, the proposed safe fallback already
exists: untrusted providers force Strict mode, and provisioning checks availability
before creating directories or launching HAL (`src-tauri/src/agents.rs:506-510`,
`614-633`). Settings also displays the unsupported-platform error
(`src/screens/settings.jsx:104-129`). This is not evidence that untrusted agents
currently run unsandboxed on Linux or Windows.

The packaging configuration lists MSI, AppImage and DEB
(`src-tauri/tauri.conf.json:20-25`). Configured targets do not, by themselves,
prove published artifacts or working non-macOS distributions. Treat "Linux/Windows
ship" as unverified, rather than inferring release availability from this list.

## Current state

- `backend()` selects Seatbelt on macOS, Landlock on Linux and Unsupported
  elsewhere. Both non-macOS cases fail closed in `available()`
  (`src-tauri/src/sandbox.rs:114-135`).
- Untrusted providers cannot opt out of Strict. The agent record is inserted in
  `provisioning` before the asynchronous availability check, so rejection leaves
  a failed agent with its error saved, rather than a synchronous spawn error
  (`src-tauri/src/agents.rs:508`, `540-555`, `575-587`, `625-626`).
- The UI has an unavailable badge and platform error in the expandable Settings
  section, and displays agent errors in agent detail and list views
  (`src/screens/settings.jsx:104-129`, `src/screens/agents.jsx:660`, `834`).
- Trusted agents are a different security posture: the vault-hiding trusted
  profile returns `None` off Seatbelt, and trusted command wrapping can return
  the original argv (`src-tauri/src/sandbox.rs:282-313`). This is not Strict
  fallback and must not be presented as equivalent isolation.
- HAL already has Linux kernel sandbox primitives: runtime Landlock capability
  probing, validated per-command application and fail-closed non-Linux behavior
  (`../hal/src/security/exo_sandbox.rs:234-271`). Its process admission wrapper
  is likewise Linux-specific (`../hal/src/security/exo_process.rs:403-429`).
  These APIs protect commands, not automatically the externally launched Philium
  HAL daemon: Philium separately accepts a process wrapper for that launch
  (`src-tauri/src/hal.rs:42-44`, `109-113`). HAL's existing work therefore does
  not make Philium's Landlock placeholder implemented.

## Where the fix lives

**Philium-only** for the smallest safe completion: explicit platform support
labeling, earlier preflight, and regression/acceptance evidence. No HAL change is
required to retain the existing refusal policy
(`src-tauri/src/sandbox.rs:124-135`, `src-tauri/src/agents.rs:625-626`).
A future native Linux/Windows sandbox is separate, larger work, not a prerequisite
for this fallback-based resolution (`docs/GAPS.md:210-215`).

## Proposed design

1. Keep the existing non-macOS refusal. Reuse `available()` during spawn after
   resolving provider trust, before inserting the agent or assigning its task.
   Keep the provisioning check for restart/resume and defense in depth. The
   relevant ordering is visible at `src-tauri/src/agents.rs:506-510`, `540-564`,
   `614-626`.
2. Expose the existing sandbox status at agent creation/model selection, with
   clear text that untrusted/Strict agents are unavailable on this platform.
   Do not silently change provider trust or downgrade Strict. Reuse the Settings
   status/error presentation (`src/screens/settings.jsx:104-129`).
3. Label non-macOS packages as lacking Strict/untrusted-agent support wherever
   those configured targets are distributed. Do not claim verified shipping
   based only on `src-tauri/tauri.conf.json:22`.
4. Defer native backend implementation. Any later backend must wrap HAL itself
   and host-run shell paths, not only HAL tools; those paths currently use the
   Philium wrapper (`src-tauri/src/agents.rs:795`, `src-tauri/src/mcp.rs:840`,
   `src-tauri/src/agentshell.rs:122`). Resolve capabilities at runtime, not from
   hardcoded kernel/client versions (`AGENTS.md:5-7`).

## Acceptance checks

Planned checks, not executed in this documentation-only investigation:

- Real running app matrix: macOS, Linux and Windows. On Linux and Windows,
  select an untrusted provider and create an agent. Observe the platform reason,
  no HAL process, no model request and no newly assigned task/worktree resources.
  Repeat with explicit Strict on a trusted provider, retry/resume and a helper.
- On both unsupported platforms, open Settings and agent creation. Confirm the
  unavailable reason is visible and no secure/active sandbox claim is shown.
  Verify explicitly trusted non-Strict operation is labeled as such.
- On macOS, create a Strict agent, complete two queries, verify denied private
  reads and forbidden direct egress, then remove it and verify owned cleanup.
  Coordinate egress proof with I6 rather than treating a startup check as proof.
- Add platform-aware tests for unavailable backend errors and spawn/preflight
  ordering. Test that explicit `strict: false` never overrides provider distrust,
  and that restart retains the provisioning refusal.
- Inspect actual distributed package metadata/support notices if packages exist.
  Keep absent Linux/Windows environments or artifacts recorded as blocked, not
  passed. The current evidence is source inspection only.

## Dependencies and risks

- I1 supplies cross-platform regression execution, while I6 owns direct-egress
  enforcement proof (`docs/GAPS.md:182-187`, `217-222`).
- I4 must account for non-macOS trusted agents lacking the Seatbelt vault-hiding
  profile (`docs/GAPS.md:200-208`, `src-tauri/src/sandbox.rs:282-305`). Do not
  misclassify this separate trusted-agent exposure as a Strict bypass.
- Lower ranking from "missing fail-closed safety" to "support clarity and proof":
  refusal and UI already exist. Native sandbox parity remains substantial work
  (`src-tauri/src/sandbox.rs:124-135`, `src/screens/settings.jsx:104-129`).
- No pinned model IDs, prices or dependency versions are needed for this design
  (`AGENTS.md:5-7`).

## Size

**S** for preflight, visible support labels and focused regression coverage,
building on existing refusal/status APIs (`src-tauri/src/sandbox.rs:124-135`,
`src/screens/settings.jsx:104-129`). Native Linux/Windows parity is a separate
large project, not included in this estimate.
