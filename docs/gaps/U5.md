# U5: Cross-session search and fork from any message

## Status (2026-11-23): closed on the Philium side

- **Search**: `agents.search_history` (`src-tauri/src/agent_history.rs::search`)
  scans every agent's saved HAL event journal (read-only, same guards as replay)
  for all query terms, case-insensitive, over user messages and completed
  replies only. Hits carry agent, `seq`, role, time and a snippet. The Agents
  list has a "Search all conversations" box; a hit opens that agent and scrolls
  to and highlights the message. The scoped MCP `session_search` is unchanged.
- **Fork from any message**: every user message and finished reply has
  "Fork from here". `agents.fork_context` returns the transcript up to and
  including that message (a reply is completed, never anything after), and a
  new agent is spawned with that prefix as its opening brief, on the parent's
  branch. No tool is replayed and files are not rewound (A1).
- **Remaining HAL-side limit**: HAL is read-only for this lane and has no
  history-import endpoint, so the child receives the prefix as text context,
  not as native HAL messages. Attachments and tool output are not copied.
- Tests: `cargo test history` (search across agents, peer-session isolation,
  read-only bytes, JSON keys not matched, fork boundary/invalid seq).

## Verdict

**Partly true.** Search is not absent: `library.sessions` exposes cross-agent
history lookup, including raw transcript excerpts (`src-tauri/src/library.rs:2638-2721`,
`3775-3783`). However, it is bounded rather than exhaustive, and no frontend
consumer of `library.sessions` or `event_ref` was found by `rg` over `src/`.
The visible fleet search only matches agent metadata
(`src/screens/agents.jsx:1089-1101`). Historical-message forking is missing:
`/fork` calls `agents.spawn` with branch and handoff text, not a source session
or message boundary (`src/screens/agents.jsx:571-584`). The audit's description
of a current-state fork overstates conversation continuity.

## Current state

- Philium searches up to 60 recently active agent rows and at most 300 HAL
  journal entries per agent, returning at most 25 results and five excerpts
  per agent. Matching is tokenized substring scoring, not a complete full-text
  index (`src-tauri/src/library.rs:2646-2661`, `2685-2701`, `2766-2767`).
- A same-repository `session_search` MCP tool already exists, explicitly
  excluding cross-repository and imported history (`src-tauri/src/mcp.rs:272`).
  Do not replace that agent-facing scope with unrestricted owner search.
- Search results contain agent IDs, snippets and event references, so reuse
  the existing result contract rather than inventing another search store
  (`src-tauri/src/library.rs:2695-2699`, `2748-2761`).
- Saved stopped-agent transcripts already have a paged UI and retry state
  (`src/screens/agents.jsx:668-672`). Saved events are read from the recorded
  session and ordered by sequence (`src-tauri/src/agent_history.rs:171-185`).
- The current fork carries role, repository, model, strict flag, branch and
  a textual handoff, with no transcript copy (`src/screens/agents.jsx:571-584`).
  A new agent's HAL session is created with workspace, title and model only
  (`src-tauri/src/agents.rs:818-829`). Transcript messages render without a
  fork action (`src/ui/conversation.jsx:542-548`).
- HAL exposes message IDs and compacted flags through `GET /sessions/{id}/messages`
  (`../hal/src/server/sessions.rs:468-485`). Its create-session body has no
  source-session, boundary or history-import field
  (`../hal/src/server/sessions.rs:28-64`), and its session routes contain no
  fork endpoint (`../hal/src/server/mod.rs:459-503`). Messages are durable
  JSON records with monotonic SQLite row IDs (`../hal/src/session/db.rs:1087-1104`).

## Where the fix lives

**Both.** Philium owns search coverage, owner-facing search/navigation,
message actions and agent/worktree lifecycle. HAL needs a minimal validated
history-prefix export/import primitive in `src/server/sessions.rs`,
`src/server/mod.rs`, `src/session/mod.rs` and `src/session/db.rs`. Existing
creation cannot accept history (`../hal/src/server/sessions.rs:28-64`).
HAL remains read-only for this grounding task, as required by
`docs/LANES.md:13`.

## Proposed design

1. Extend `library.sessions` with cursor-based coverage of all retained
   Philium agent histories. Index searchable text incrementally with stable
   agent/session/event/message identity. Preserve scoped MCP lookup separately.
   Replace silent scan caps with pagination and explicit unavailable-history
   diagnostics. No need to search arbitrary imported external histories for U5.
2. Add an owner-facing session-search view with query, repository/agent filters,
   snippets and result counts. Selecting a result opens the existing saved
   transcript, loads the containing page and highlights the exact message.
3. HAL exports a read-only prefix through a validated source message ID and
   imports that prefix into a fresh session in the destination agent's HAL
   store. Return new IDs plus source lineage. A cross-store transfer is needed
   rather than assuming the destination can dereference the source session.
4. Copy transcript/context and referenced attachment bytes, not credentials,
   permission approvals, running processes, spend counters or tool execution.
   Reconstruct the selected boundary without later compacted summaries leaking
   future turns. Include complete tool-call/result groups or explicitly reject
   an unsafe boundary. Never replay tools to reconstruct a conversation.
5. Add “Fork from here” to historical messages and search results. Preserve
   `/fork` as an explicitly labelled branch/handoff action, or route it to the
   newest supported history boundary. Record lineage and show copied context.
6. State clearly that a conversation fork does not restore historical files.
   Use the existing branch/worktree creation path for the current checkout.
   Historical filesystem restoration belongs to A1, not an implicit U5 promise.

## Acceptance checks

These are proposed checks, not executed acceptance results. This pass used
read-only code inspection only, per `docs/gaps/README.md:15-17`.

- In the running app create two agents with unique phrases, stop one, restart
  Philium and search both phrases. Open each result at its exact message,
  including a result beyond 60 agents and beyond 300 events. Empty queries,
  pagination, Unicode and unavailable/deleted histories must be understandable.
- Fork from an older user message and an assistant reply in the real transcript,
  then fork from a search result. Ask the child about a fact before the boundary
  and a secret phrase after it. The first must be present and the latter absent.
  Run a second query, restart/resume the child and confirm durable lineage.
- Repeat with attachments, tool output and a compacted conversation. Verify
  complete tool groups, usable images and no later-summary leakage. Parent
  history/worktree must remain unchanged and no old tool must execute again.
- Check Strict/Standard and cross-repository isolation through the running app
  and actual MCP calls: unrestricted owner search must not broaden agent access.
  Cancel a failed import and verify no orphan agent, worktree or HAL resource.
- Add regression tests for cursor/index completeness, stable hit navigation,
  boundary validation, attachment isolation and atomic prefix import. Run the
  applicable Rust and frontend checks when implementation is authorized.

## Dependencies and risks

- A1 is required only if the product promises historical file restoration;
  the current action only selects the parent's branch
  (`src/screens/agents.jsx:579`). U5 must not conflate transcript and file state.
- A7 must coordinate compaction semantics: HAL returns compacted flags as well
  as messages (`../hal/src/server/sessions.rs:476-481`).
- Search security must retain the same-repository agent contract
  (`src-tauri/src/mcp.rs:272`). Search indexing and forked attachments are
  additional copies of sensitive history and need matching deletion/retention.
- No model/version/price literals are needed. Resolve selected models through
  the existing provider path, consistent with `AGENTS.md:5-7`.
- Ranking correction: search is an extension and UI exposure task, not greenfield.
  Forking is larger than a message button because the current fork has no
  conversation ancestry (`src/screens/agents.jsx:574-580`).

## Size

**L** overall: bounded search already exists, but complete coverage, exact hit
navigation and safe cross-store conversation-prefix import require coordinated
Philium/HAL work. Search-only delivery can be split from historical forking.
