# A6: Web fetch/search and code intelligence tools

## Verdict

**Partly true.** Dedicated fetch/search tools are absent from the inspected Philium MCP catalog and HAL default registry, but the claim that agents cannot call the code index is false: the catalog includes `code_outline`, `code_symbol`, `code_find` and `code_refs`, and dispatch routes them to the index (`src-tauri/src/mcp.rs:278,520-532`; `src-tauri/src/codeindex.rs:2965-2982`; HAL `src/tools/mod.rs:292-318`). Browser navigation plus page-text snapshots already provide an interactive web-reading alternative (`src-tauri/src/browser_agent.rs:287-290`). This is source grounding, not runtime acceptance.

## Current state

- Philium already runs a bearer-authenticated local MCP endpoint with a Host-header check, and agent startup configures its streamable HTTP transport (`src-tauri/src/mcp.rs:74-82`; `src-tauri/src/agents.rs:727-735`). No second MCP server or native HAL symbol tool is needed.
- Code tools load the requesting agent's worktree/repository view and bound returned tokens. `code_symbol` returns source and `code_refs` distinguishes resolved references from possible name matches, not full compiler/LSP semantics (`src-tauri/src/codeindex.rs:3019-3034,1485-1488,1616-1617,1633-1670`).
- External repository code reads require a code-scoped grant. Remote PR context is explicitly refused in this dispatch path (`src-tauri/src/mcp.rs:520-530`).
- `codeinspect` is bounded inspection of graph-selected snapshots, with a separate internal dispatch, rather than the missing agent symbol interface asserted by the audit (`src-tauri/src/codeinspect.rs:1,127,160,540`; `src-tauri/src/codeindex.rs:2965-2982`).
- Browser tools include navigation, text snapshots, evaluation and user-visible tabs. Strict navigation checks a per-agent URL policy; this is partial web capability, not a structured fetch/search API (`src-tauri/src/browser_agent.rs:287-302,328-352`).
- HAL's built-in registry has filesystem, process, Git, browser and task tools and conditionally an MCP connector, but no dedicated fetch/search or LSP entries (`HAL src/tools/mod.rs:292-318`). Philium also merges configured external MCP servers, skipping that merge for Strict agents (`src-tauri/src/agents.rs:735`; `src-tauri/src/mcp_servers.rs:120-125`). Thus an optional external server can supply capabilities, but is not a first-party default.
- Strict process egress uses loopback confinement and an authenticated allowlist proxy. New HTTP inside the Philium host must not assume the agent process sandbox covers it (`src-tauri/src/sandbox.rs:262-264,346-378,489-537`).

## Where the fix lives

**Philium-only** for the stated outcome. Extend the existing catalog and dispatch in `src-tauri/src/mcp.rs`; put fetching, extraction and search adapters in a small backend module. Reuse `sandbox.rs` policy decisions for host-side requests. Keep the existing `codeindex.rs` MCP interface. HAL already accepts the configured MCP connection (`src-tauri/src/agents.rs:727-735`; HAL `src/tools/mod.rs:314-318`). A true language-server protocol implementation would be a separate enhancement, not required for the structural-symbol tools listed in A6.

## Proposed design

1. Add authenticated, read-only `web_fetch` and `web_search` tools to the existing Philium MCP service. Return source URLs, retrieval timestamps, bounded excerpts and explicit truncation/error metadata. Fetch should expose final URL and content type and avoid forwarding browser cookies or bearer credentials.
2. Centralize per-agent host authorization for fetch and search. Check initial destinations, every redirect and resolved connection addresses. Deny private/link-local/metadata endpoints unless an explicit narrowly scoped local-access capability permits them. Bound bytes, redirects, decompression, concurrency and duration. Check revocation during requests and cancel owned requests on agent teardown.
3. Resolve search configuration and capability at request time from enabled providers/adapters and secret references. Do not infer a search service from model names. Return a clear setup/unavailable result when none is configured. Never embed vendor versions, model IDs, prices or static service catalogs. Repository policy requires runtime resolution (`AGENTS.md:5-8`).
4. Keep `code_outline`, `code_symbol` and `code_refs` as the symbol workflow. Preserve exact-versus-possible labels and existing repository grant checks. Improve discovery/help only if runtime checks show agents miss the already-connected tools (`src-tauri/src/codeindex.rs:2974-2980`; `src-tauri/src/mcp.rs:525-532`).
5. Treat fetched text and search snippets as untrusted data, not tool instructions. Require existing approval semantics or narrower explicit web permissions before network access, with audit records that redact credentials.

## Acceptance checks

These are proposed checks, not executed in this docs-only grounding pass.

- **Running-app workflow:** create an agent on a real repository, ask it to outline a file, retrieve a definition and identify references. Inspect actual MCP calls and source line spans, including possible-reference labels. Edit the agent worktree and ask again to verify freshness. Deny a cross-repository request, grant code scope, retry, revoke and confirm denial. Existing dispatch fixtures provide regression starting points (`src-tauri/src/mcp.rs:1213-1233,1322-1323,1369-1370,1424`).
- **Running-app web workflow:** configure a search adapter through the app, ask a real agent a current question, observe `web_search` followed by `web_fetch`, and manually verify citations against returned source pages. Repeat a second query, change/disable the adapter without rebuilding, and verify a useful unavailable result rather than fabricated results.
- **Policy matrix:** run Standard and Strict agents with allowed and denied hosts. Test allowed-to-denied redirects, DNS-to-private destinations, metadata addresses, unsupported schemes, oversized/decompression payloads and timeout/cancellation. Confirm denials happen before outbound connection and tokens never reach origin pages or logs.
- **Isolation/cleanup:** use two agents with different grants and host policies, verify neither inherits the other's access, stop one during a slow fetch, and confirm only its request is cancelled. Reconnect and repeat successfully.
- Add focused tests for policy/redirect enforcement, extraction bounds, adapter re-resolution and MCP schemas. Run applicable backend/frontend regressions when implementing. Unit tests alone do not satisfy the running-app checks.

## Dependencies and risks

- **I6:** host-side fetch/search must apply network policy independently of the process sandbox. Existing proxy policy and browser URL checks are reuse points, not proof a new HTTP path is protected (`src-tauri/src/sandbox.rs:262-264,489-537`; `src-tauri/src/browser_agent.rs:328-352`).
- **I4:** use secret references and redact search-provider credentials; configured MCP server serialization already resolves secret-backed values (`src-tauri/src/mcp_servers.rs:120-124`).
- SSRF, redirects, untrusted page instructions, query privacy, per-provider billing and extraction limits need explicit implementation tests. Avoid presenting structural name resolution as compiler-accurate semantics (`src-tauri/src/codeindex.rs:1485-1488,1616-1617`).
- Ranking implication: remove the missing-agent-code-index premise. Prioritize safe first-party web tools rather than implementing a duplicate symbol server. Optional configured MCP servers and browser tools already offer partial substitutes (`src-tauri/src/mcp_servers.rs:120-125`; `src-tauri/src/browser_agent.rs:287-290`).

## Size

**M** for policy-correct first-party web tools plus runtime search configuration and app acceptance. Code-index exposure is already implemented (`src-tauri/src/mcp.rs:278,520-532`), so a new HAL/LSP integration is outside this gap's minimum scope.

## Philium side (done)

`src-tauri/src/web.rs` adds `web_fetch` and `web_search` to Philium's MCP
service. Every hop is checked (http/https, no URL credentials, all resolved
addresses public, so loopback/private/link-local/metadata are refused) and the
request connects only to the checked addresses. No cookies or tokens are sent;
redirects are capped, bodies bounded with `truncated`, and results carry
`final_url`, `content_type`, `fetched_at` and `untrusted:true`. Strict agents
get neither tool. Search has no built-in service: it uses the person's
`setting.web.search_url` template (`{q}`) and otherwise says how to set it up.
Code symbols stay on the existing `code_*` tools. Tests:
`web::tests::only_public_http_targets_pass`, `web::tests::html_and_search_helpers`.
Open: a Settings field for the search URL and per-agent web approval. No HAL
change needed.
