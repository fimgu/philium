# A5: Dollar cost tracking

## Verdict

**Partly true.** The claim that there is no price table or per-agent dollar cost is stale: model discovery imports prices, requests persist a calculated cost, and summaries group costs by agent (`src-tauri/src/providers.rs:641-655`, `src-tauri/src/stats.rs:39-55`, `src-tauri/src/stats.rs:337-344`). Cache-sensitive pricing, explicit subscription inclusion and conversation/session attribution remain genuine gaps: the formula uses only input/output rates, and the request/activity schemas have no conversation identity or billing classification (`src-tauri/src/stats.rs:42-55`, `src-tauri/src/gateway.rs:73-98`, `src-tauri/src/db.rs:91-96`).

## Current state

- **Philium pricing already exists.** Discovery parses live `/models` pricing into USD per million input/output tokens (`src-tauri/src/providers.rs:632-655`). Providers UI exposes and edits these prices (`src/screens/providers.jsx:181-199`, `src/screens/providers.jsx:226`). However, refresh uses `COALESCE(existing, discovered)`, preserving an old non-null rate even when the live rate changes (`src-tauri/src/providers.rs:814-821`). It does not distinguish manual overrides from discovered prices there.
- **Request and aggregate dollars already exist.** `stats::record` deduplicates terminal activities and persists `(input * price_in + output * price_out) / 1M`, or NULL if either rate is missing (`src-tauri/src/stats.rs:29-55`). Aggregation preserves an unpriced-request count and provides provider, model, agent and repository groups (`src-tauri/src/stats.rs:131-141`, `src-tauri/src/stats.rs:337-344`). Stats UI displays “Known cost” and unknown-price counts (`src/screens/stats.jsx:208-213`). This is an estimate, not an upstream billing reconciliation.
- **Cache accounting is insufficient for pricing.** Gateway captures cache-read tokens, folds Anthropic cache reads and writes into total input, but does not retain cache-write tokens separately in `Activity` (`src-tauri/src/gateway.rs:90-92`, `src-tauri/src/gateway.rs:512-529`). The cost calculation ignores even the retained read-token count (`src-tauri/src/stats.rs:42-43`).
- **Subscriptions are not a billing state.** Provider kinds identify subscriptions (`src-tauri/src/providers.rs:43-49`, `src-tauri/src/providers.rs:67`), but recording looks up rates by provider/model without checking that kind (`src-tauri/src/stats.rs:42-55`). A priced subscription can therefore receive a synthetic dollar estimate; an unpriced subscription is counted as unknown rather than included (`src-tauri/src/stats.rs:139-140`).
- **Session is not conversation identity.** Stats' `SESSION` is a process-wide deduplication namespace, not a HAL session (`src-tauri/src/stats.rs:9-11`, `src-tauri/src/stats.rs:33-41`). Gateway activities identify an optional agent only; requests have no HAL-session column (`src-tauri/src/gateway.rs:95-98`, `src-tauri/src/db.rs:91-96`). Agents do persist their HAL session separately (`src-tauri/src/agents.rs:818-849`). Existing retention deletes request rows older than 30 days, so lifetime totals require an explicit retention decision (`src-tauri/src/stats.rs:19-22`).
- **HAL is token-only at its public usage boundary.** `Usage` carries prompt/completion counts and `ModelStat` carries requests plus those counts, with no money or cache dimensions (`../hal/src/provider/mod.rs:224-237`, `../hal/src/session/db.rs:105-111`). Session budgets persist total/input/output token limits (`../hal/src/session/db.rs:272-274`, `../hal/src/session/db.rs:779-799`). Philium routes its configured providers through its gateway, so HAL does not need to own price estimation (`src-tauri/src/providers.rs:289-310`).

## Where the fix lives

**Philium-only for current gateway-routed Philium conversations.** Extend `gateway.rs` usage metadata, `providers.rs` runtime pricing, `stats.rs` persistence/aggregation and the stats/request/session UI. Add schema extensions in the owning module's `init`, per `docs/LANES.md:21-24`.

For Philium-owned agents, bind the already persisted HAL session to request attribution at request start, rather than resolving a mutable current session when a request completes (`src-tauri/src/agents.rs:818-849`). Desk conversations need an equivalent session-scoped gateway credential/context. If accurate attribution of independent HAL subagent sessions cannot be established at that boundary, a follow-up **HAL change** must propagate an opaque session/request identifier in gateway-bound calls. Do not infer session identity from a shared agent token or charge parent and child twice; current `Activity` has no such discriminator (`src-tauri/src/gateway.rs:73-98`).

## Proposed design

1. Extend runtime rate records with input, output, cache-read and cache-write rates, relevant cache TTL/tier dimensions, currency, source, retrieval timestamp and effective snapshot identity. Consume provider-returned pricing where available, otherwise a vetted live catalog. Match exact provider/model identities; do not silently reuse another provider's rate. Unknown dimensions remain unknown. Store manual overrides separately so automatic refresh can actually replace discovered rates.
2. Normalize usage into non-overlapping ordinary input, cached input, cache creation and output counts. Preserve provider semantics and cache-write TTL details before request translation/usage flattening. Compute from those components exactly once using a persisted rate snapshot; use fixed-point decimal units with checked arithmetic rather than accumulating floating-point drift.
3. Persist per-request billing state: `estimated`, `included`, or `unknown`, plus reason and component costs. Determine `included` from subscription provider kind before any rate lookup. Missing rates or missing usage are not zero cost. Historical estimates keep their snapshot when catalogs refresh; older rows with missing dimensions stay explicitly incomplete.
4. Persist scoped session identity and stable agent identity at request start. Add session grouping and request details alongside existing agent totals. Show known USD, included requests and unknown requests separately, and expose cache read/write components and price freshness. Specify whether session totals are retained beyond the existing request-retention window.
5. Keep prices and model selection runtime-resolved. No embedded price/model table in normal source; any truly unavoidable fallback belongs only in `src-tauri/src/pins.rs`, with refresh rationale (`AGENTS.md:5-7`). Dollar budget enforcement is separate from this gap's cost-display acceptance.

## Acceptance checks

These are proposed checks, not executed acceptance results. This grounding task permits read-only investigation, not builds or launching the app (`docs/gaps/README.md:15-22`).

- Unit/integration fixtures: ordinary input/output, cache hit, cache creation with each supported TTL, absent usage, absent rates, subscription with manually populated prices, fractional arithmetic, changed live prices and explicit overrides. Assert cache tokens are never charged twice and incomplete estimates are not presented as complete totals.
- Persistence/API checks: one terminal activity produces one request charge; retries are distinct attempts, repeated activity updates are not. Reloading preserves snapshot and billing classification. Verify request sums equal session and agent subtotals, including mixed included/unknown traffic, model switches and concurrent sessions.
- **Running app, real paid API:** choose a runtime-discovered model with source-verified live rates, send a request in a desk conversation and two requests through an agent. Make the second eligible request reuse context. Inspect returned usage and stored rate snapshot, then reconcile component arithmetic against request detail, session total and agent total. Confirm a real cache hit when the upstream provides it, rather than assuming the second request hits.
- **Running app, subscription:** select a signed-in subscription, send two queries and verify request/session/agent displays say “included” without synthetic USD, including when model metadata has prices. Switch that session to a paid API and verify the categories remain separate.
- **Running app, isolation and restart:** run two sessions concurrently, fork/resume as supported, and verify no cross-session charges or parent/child double counting. Restart the app and confirm the same totals. Exercise catalog outage and unknown model, verifying visible unknown/stale provenance rather than zero spend. Verify cleanup of any acceptance-created agents and credentials.

## Dependencies and risks

- **A4 dependency:** preserve cache-write counts and TTL distinctions before calculating prices. Current normalization loses them (`src-tauri/src/gateway.rs:512-529`). Coordinate schema changes rather than implementing two competing usage normalizers.
- **Freshness defect increases priority within the remaining scope:** live refresh currently cannot replace existing non-null rates (`src-tauri/src/providers.rs:818-820`). This can silently misprice already-supported requests, not merely omit a future feature.
- **Attribution/privacy:** session metadata must be authenticated, opaque and scoped to the gateway token, not accepted from arbitrary model-controlled headers. Current gateway attribution is token-to-agent only (`src-tauri/src/gateway.rs:95-96`). Never persist tokens or prompt bodies in price provenance.
- **Unknown versus included:** retain that distinction throughout totals and UI; the current aggregate only distinguishes NULL cost from known cost (`src-tauri/src/stats.rs:139-140`). Do not promise invoice accuracy where service tiers, long-context bands or provider-specific billable dimensions cannot be resolved.
- **Ranking correction:** do not schedule a new cost table or token-to-dollar aggregation from scratch. Those already exist (`src-tauri/src/stats.rs:39-55`, `src-tauri/src/stats.rs:337-344`). Focus A5 on trustworthy pricing refresh, cache billing and session attribution.

## Size

**M** for the current Philium gateway-routed scope: reuse existing cost persistence and grouped UI, but extend rate provenance, usage normalization and session attribution. **L** if independently attributed HAL child sessions require an upstream metadata contract.
