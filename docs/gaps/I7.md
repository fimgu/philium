# I7. Logging and diagnostics

## Verdict

**Partly true.** The missing leveled, rotating Philium operational log and
shareable diagnostics remain valid gaps, but “only a custom ctx.log_event”
overstated the starting point: audit events already have structured JSON,
timestamps and agent IDs (`src-tauri/src/ctx.rs:109-131`,
`src-tauri/src/db.rs:98-100`), HAL stderr already has a captured tail
(`src-tauri/src/hal.rs:137-150`), and HAL already initializes leveled tracing
(`~/Developer/hal/src/main.rs:574-586`).

## Current state

- Philium audit persistence stores `ts`, `kind`, `agent_id`, and serialized body,
  emits the event to the UI, and returns a durable event reference. Oversized
  bodies become a size plus prefix record, not an unbounded dump
  (`src-tauri/src/ctx.rs:109-132`; size ceiling at `:26`). This is structured
  application data, but the schema has no severity or span fields
  (`src-tauri/src/db.rs:98-100`).
- Home requests the latest 30 audit events; the backend event RPC caps each
  result at 1,000. That is read pagination, not storage retention
  (`src/screens/home.jsx:53`, `src-tauri/src/main.rs:291-296`). The inspected
  append path contains no pruning (`src-tauri/src/ctx.rs:121-132`).
- HAL launch captures the last 20 stderr lines in memory and echoes each raw
  line with `eprintln!`; startup and exit reporting select one error line
  rather than exposing the complete tail (`src-tauri/src/hal.rs:137-174`,
  `:232-244`). The desk watcher records that reason and restarts HAL
  (`src-tauri/src/main.rs:454-470`). The tail is line-bounded, not byte-bounded
  (`src-tauri/src/hal.rs:143-149`).
- HAL supports an environment filter and defaults to info/warn or debug with
  verbose mode. Its formatter writes through `LogWriter`, normally to stderr,
  not a rotating file (`~/Developer/hal/src/main.rs:574-586`, `:401-424`).
- Philium's direct dependency list has no tracing subscriber or rolling-log
  dependency (`src-tauri/Cargo.toml:9-39`). Source searches found no diagnostics
  bundle/copy action or operational log rotation. The event RPC only returns
  rows, not a sanitized export (`src-tauri/src/main.rs:291-298`). This is a
  source-grounding observation, not a running-product acceptance result.
- Secret scanning primitives exist for strings and JSON values, and selfdev
  wraps that scanner for report text (`src-tauri/src/guard.rs:44-99`,
  `src-tauri/src/selfdev.rs:124-128`). Neither the audit append nor stderr echo
  invokes those primitives (`src-tauri/src/ctx.rs:109-131`,
  `src-tauri/src/hal.rs:143-146`). JSON scanning processes values, not keys
  (`src-tauri/src/guard.rs:94-99`).

## Where the fix lives

**Philium-only.** Add a small diagnostics/logging module, initialize it from
`src-tauri/src/main.rs`, connect the existing HAL stderr reader in
`src-tauri/src/hal.rs`, and add a Settings action in
`src/screens/settings.jsx`. HAL already supplies leveled stderr without a new
upstream interface (`~/Developer/hal/src/main.rs:574-586`, `:413-424`). Keep HAL
read-only as required by `docs/LANES.md:13`.

## Proposed design

1. Initialize a structured JSON tracing sink before backend initialization,
   with timestamp, level, module, operation and optional agent/session/request
   correlation. Keep the existing audit-event API and durable references
   separate from debug verbosity. Do not dump RPC arguments or request bodies.
2. Add bounded file rotation by byte size plus retained-file/age limits under
   app data. Restrict file access, retain the writer guard through shutdown,
   and degrade visibly but safely on disk-full or permission failures. Add
   explicit audit retention separately if required, without silently deleting
   audit history as a side effect of debug-log rotation.
3. Route HAL stderr through the same redaction boundary before echo/persistence
   and retain a byte- and line-bounded tail. Label child origin and correlation;
   do not pretend the existing human-readable HAL formatter is structured JSON.
   Snapshot stopped children before restart so the useful crash tail survives.
4. Provide a versioned, size-bounded **Copy diagnostics** text bundle with
   runtime app/build/platform metadata, recent sanitized errors, log excerpts
   and HAL tails. Show scope and preview, then copy only on explicit action.
   Exclude database dumps, credentials, environment dumps, prompts and gateway
   request/response bodies by default.
5. Use allowlisted metadata and sensitive-key suppression first, then the
   existing scanner as defense in depth. Cover authorization headers, arbitrary
   session/access tokens, URL queries and home paths explicitly. Apply filtering
   before local persistence and again before export, including multiline and
   truncated input. Resolve versions from build/runtime metadata, not literals
   (`AGENTS.md:5-7`).

## Acceptance checks

These are implementation acceptance criteria, not tests executed in grounding.

- Unit checks: valid structured records and level filters, correlation fields,
  UTF-8/multiline/huge stderr bounds, restart-tail preservation, rotation and
  retention limits, writer flush and disk-full fallback.
- Security checks: plant synthetic secrets in event fields, object keys, HAL
  stderr, URLs and errors. Inspect every rotated file and copied bundle for
  absence of originals. Include unknown-format bearer tokens, split/multiline
  secrets and truncated private keys. Verify restrictive log-file access.
- Real running-app workflow on each supported desktop platform: launch Philium,
  configure a provider with synthetic test credentials, submit a fresh desk
  query, induce a controlled provider error and test HAL failure/restart, then
  run a second query. In Settings, preview and copy diagnostics, paste into a
  local editor, and verify metadata, correlated failure and complete bounded
  HAL tail with no credentials or conversation bodies. Cancel must not copy.
- Force rotation through the real sink, restart the app, repeat copy, and check
  retained-file/byte bounds, restart durability and normal query behavior.
  Collect current-head observations before claiming workflow acceptance.

## Dependencies and risks

- Coordinate I4: safe credential storage does not make logging/export safe.
  Current audit and HAL paths accept raw strings (`src-tauri/src/ctx.rs:109-131`,
  `src-tauri/src/hal.rs:143-146`). Redaction is a security requirement, not polish.
- Coordinate I1/I8 for regression automation. No new version/model/price pins
  are needed, and unavoidable literals follow `AGENTS.md:5-7`.
- Export scope must stay narrow: Activity already exposes forwarded bodies and
  response excerpts (`src/screens/activity.jsx:279-310`), which must not become
  an implicit diagnostics attachment.
- Ranking correction: HAL tracing and stderr capture are reuse opportunities,
  not missing foundations. Keep the gap for rotation, safe export and the
  unredacted operational boundary, rather than replacing HAL's logging stack.

## Size

**M.** Existing audit, HAL capture and scanner reduce groundwork, but the shared
redaction boundary, reliable rotation and actual clipboard workflow still need
integration and security coverage.
