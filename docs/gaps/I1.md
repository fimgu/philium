# I1. CI

## Verdict

**Verified for missing checked-in CI, with existing local groundwork.** On
2026-11-23, `git ls-files '.github/*' '*gitlab*' '*Jenkins*'` returned no paths
in either Philium or HAL, and root directory listings showed no `.github`.
These negative observations have no source line to cite. They establish the
repository state, not whether an external service or remote branch has CI.
The register's stronger claim that nothing runs on push is therefore not
provable from this checkout alone (`docs/GAPS.md:182-186`).

HAL already supplies a local `ci` target invoking lint and tests
(`../hal/Makefile:82-100`). Philium already has frontend tests, contrary to I8's
blanket wording: a test uses Node's built-in runner and strict assertions
(`src/lib/plain-error.test.js:1-21`), but root scripts expose neither tests nor
lint (`package.json:5-10`). CI is wiring and reproducible environment work,
not creating every test suite from scratch.

## Current state

- Philium exposes Vite build, Tauri, pilot packaging and sidecar commands
  (`package.json:5-10`). Tauri runs the frontend build before packaging and
  requires the external HAL server (`src-tauri/tauri.conf.json:6-10,20-25`).
- The sidecar script defaults to a sibling HAL checkout, builds the release
  server, and stages a host-triple-suffixed binary. `HAL_DIR` can override the
  source location (`scripts/sidecar.sh:2-11`). Generated binaries are ignored
  (`.gitignore:3-5`), so a clean runner must produce them rather than depend
  on a developer's staged executable.
- The backend's Tauri build script also links the macOS clang runtime when
  available, relevant to release/LTO builds (`src-tauri/build.rs:1-18`). Its
  dependency set includes ONNX binary downloads (`src-tauri/Cargo.toml:32`),
  so a clean-runner dependency/bootstrap path needs explicit verification.
- `pins::tests::no_stale_pins` scans backend and frontend source and fails on
  prohibited version-like literals (`src-tauri/src/pins.rs:120-154`). It must
  remain part of normal `cargo test`, without filtering or weakening it.
- There is additional test groundwork beyond root frontend tests: render
  tests use Node's runner (`scripts/render/conversation-view.test.mjs:1-12`),
  and a real-backend self-development script runs an explicitly ignored test
  with a scripted model, isolated clone and cleanup trap
  (`scripts/selfdev-e2e.sh:2-4,9-31`). That is not native UI/provider acceptance.
- HAL's local quality commands are `cargo test`, Clippy with warnings denied,
  formatting checks, and `make ci` for lint plus tests
  (`../hal/Makefile:82-100`). These are reusable ingredients, not a hosted
  workflow. HAL remains read-only for this lane (`docs/LANES.md:13`).

## Where the fix lives

**Both, with no HAL runtime/interface change required.** Philium owns its new
workflow files, CI entry scripts and frontend command wiring. HAL needs its own
upstream workflow to cover pushes and PRs there, reusing `Makefile:82-100`.
Philium also needs a clean-runner HAL checkout for `scripts/sidecar.sh:4-10`.
Philium CI alone cannot establish HAL repository push coverage.

## Proposed design

1. Add push/PR workflows with read-only repository permissions, concurrency
   cancellation and bounded timeouts. Keep signing and publication out of PR
   jobs, especially fork PRs. Resolve current supported runners/toolchains and
   action releases when implementing, rather than copying stale versions.
2. Bootstrap Node dependencies from the existing lockfile, and Rust through
   current stable toolchain discovery. Resolve the current HAL source ref at
   run start, record its SHA and use that same checkout for all sidecar and
   acceptance stages. Do not rely on a developer-specific sibling directory.
   Separate dependency-refresh policy from the immutable inputs recorded for
   an individual run. Do not add provider/model/version literals outside the
   permitted pins policy (`AGENTS.md:5-7`).
3. Run full backend `cargo test` in `src-tauri`, explicitly report the stale-pin
   test result, run `npx vite build`, and expose frontend lint/test scripts in
   coordination with I8. Discover and classify existing root/render tests
   before choosing test globs, including browser prerequisites where needed.
4. Use a macOS job to stage the sidecar first, then perform a real Tauri app
   bundle build. Upload an artifact with both source SHAs and logs. Cache only
   as an optimization: require a cold-cache run and never skip required checks
   because an executable or prior artifact was cached.
5. Add HAL's upstream push/PR workflow around its local quality commands.
   Split optional resource-heavy integration jobs explicitly, with visible
   required status rather than silently treating skipped tests as success.
6. Add a trusted-release path for Developer ID signing, notarization and
   stapling after I2 supplies credentials and policy. Ordinary PR packaging
   must not claim a signed release: current macOS signing is ad hoc
   (`src-tauri/tauri.conf.json:25`).

## Acceptance checks

These are proposed checks, not executed acceptance results.

- From a clean hosted checkout with no sibling HAL, node modules, target cache
  or staged sidecar, push and PR events produce backend, stale-pin, frontend
  build/test/lint and macOS bundle statuses for the exact head SHA. Repeat
  with a warm cache and require identical check coverage.
- In disposable branches, introduce a failing Rust assertion, prohibited
  source pin, frontend assertion, lint error and broken bundle input in turn.
  Each must fail its required status and block merging. Restore every fixture.
- Verify fork PRs receive no signing/provider secrets and cannot publish.
  Verify HAL's own push/PR checks independently, not just its sidecar build.
- **Running-app workflow:** install the exact macOS CI artifact into an
  isolated test profile, select a provider/model from its live catalog,
  authenticate through the normal UI, create an agent in a disposable repo,
  ask it to inspect a known source file, and verify the response against that
  source. Send a second query, stop the agent, quit/relaunch and verify saved
  history. Record SHAs, artifact identity, checkpoints and redacted evidence.
  Remove the test profile, repo and owned processes afterward. A window
  opening, scripted model or Vite fixture alone does not satisfy this check.
- Once I2 lands, download the trusted release artifact on a clean macOS
  machine, verify signature/notarization/stapling and complete the same real
  workflow. Keep absent-platform or unavailable-provider rows visibly blocked.

## Dependencies and risks

- I8 supplies missing command wiring/lint and version alignment, but its
  assertion of no frontend tests is stale (`package.json:5-10` versus
  `src/lib/plain-error.test.js:1-21`). This lowers initial CI test setup effort.
- I2 owns signing; I3 depends on I1/I2; U3 expects CI visibility
  (`docs/GAPS.md:149-153,188-198`). Do not block basic PR checks on signing.
- HAL checkout access, sidecar availability, binary download/bootstrap costs
  and real-provider credentials need separate failure reporting, not green
  skips (`scripts/sidecar.sh:4-10`; `src-tauri/Cargo.toml:32`).

## Size

**M** for CI orchestration and clean macOS packaging, reusing existing test
surfaces. I2 signing and I8 frontend lint/version work remain separate scope.
This grounding used read-only source inspection only, with no builds or app
execution. Only this brief was created; no temporary resources need cleanup.
